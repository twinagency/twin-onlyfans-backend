## Semantic issues NOT silently resolved (decisions for the next stage)

1. **Ledger coverage for real offers.** The legacy `commerce.held` account-wide ledger-coverage requirement applies to
   `native` + media only. A `fansapi` account behaves like `synthetic` here: it relies on the fan-scoped checks
   (`_unowned`, b4 `_provider_evidence_held`) and does NOT require a completed b4 backfill before an offer. The next stage
   should decide whether to require backfill completeness for fansapi media offers.
2. **Two webhook intakes.** b2's `FansWebhookAdapter` (+ `SyntheticConversationWorker`) and b4's `FansEventIntake` both write
   `of_fans_webhook` / `of_fans_webhook_conflict`. b2's conflict fence (plan, queue, dispatch) reads the shared table, so a
   quarantine from b4's intake is honoured at those points, but b4's `accept` does not call
   `EngineService.fence_conflicted_sources` for already queued work. The orchestrator for the real path must.
3. **`SyntheticConversationWorker` is not the real orchestrator.** It still only accepts the three simulator transports.
   There is no real-path worker yet that chains `FansEventIntake` -> `EngineService.plan/queue` -> dispatch with
   `FansApiRealTransport`.
4. **Operator workflow and aliases** (gate rows 21-22) remain lab-only.
5. **Stale head assertions in older tests** (`test_conversation_holds_pg`, `test_throughput_migration_pg`,
   `test_concurrent_admission_units`, `test_native_pilot_storage_pg`) assert old `HEAD` values; see the test report for
   which of them fail on the unmerged sources too.
