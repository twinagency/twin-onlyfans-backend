## 2. Gaps (each evidenced above)

1. **Preparation cannot read history at all**: guard allowlist (`preparation.py:294-303`) refuses `/chats`, `/transactions`, `/chargebacks`; `FansBackfill._pilot_guard` is a no-op without the legacy row (`pilot_scope.current` reads scope_id==1 only, `:281`), so reusing it would run unguarded or be refused by the client guard.
2. **No fan universe**: `FansApiClient` has no chat-list method (`protocol.py:116-368`); backfill takes an explicit chat list. Provider list endpoint, cost and pagination are NOT verified here.
3. **A bad row kills the run and progress**: any `Refused` in a page (e.g. fan message with a price, `intake.py:68`; priced outgoing with bad price, `events.py:843`) -> `_finish(...,'failed')` (`backfill.py:121-122`); next `run()` ignores failed runs (`:75`) and starts a NEW run from page 1, re-spending budget, losing the failed page record.
4. **history()/transactions() failures are unclassified** (return `Result('unavailable')` without `_fail`, `protocol.py:225-230,328-340`): no Retry-After/backoff, no 429 vs schema vs auth distinction (R1 fixed vault/identity only).
5. **Non-pilot gate is weak**: `backfill_complete` returns True for any complete run covering the fan, whatever its `start_date` (`journey.py:299`).
6. **Historical purchases never reach ownership**: `isOpened` becomes only an `OfFansEvidence` unlock that `payment_evidence._link_unlock` cannot bind (no intent -> `no_matching_send`); `Message.is_paid` stays NULL, `provider_unlocked_media` is intents-only, so `_unowned` sees nothing. Previews/lockedText/isFromQueue/isTip are dropped before `Message` is written (Event has none), so free preview vs paid asset vs advertised card cannot be told apart later. No per-media `unknown` state exists.
7. **No coverage state**: `view()` hard-codes `pending`; no per-source counts, cursors, retained failed pages, or reconciliation numbers anywhere.
8. **Descriptions for FansAPI accounts have no runner** (native-only fence); cost/completeness not persisted per account.
9. **No rate/budget measurement**: only cumulative reserved counters; no per-source split (history could exhaust vault budget or the reverse), no actual-credit reconciliation, no requests/hour.
10. Webhook overlap: dedupe keys exist (messages PK, `OfIngress` key, evidence `dedupe_key`) but no recorded import boundary, no counts of duplicates/conflicts/late rows, and nothing proves the preparation account is receiving webhooks during the import.

## 3. Minimal design

**Principle**: extend the existing scope/guard/job/evidence owners; add only coverage state and message facts. No new sender, ledger, or scheduler: the existing `--preparation-only` worker (`run_preparation_once`) calls one more bounded step per account.

### 3.1 Migration `0136_history_coverage` (down_revision = placeholder `0135_*`; additive; downgrade refuses if any row exists, same pattern as 0131/0132)
All keyed by `account_id` FK `of_runtime` ondelete RESTRICT; nothing ever deleted.
- `of_fans_import_source (account_id, source PK)` source in `vault_window | chats | transactions | chargebacks | analysis`. Columns: `state` (not_started/running/partial/complete/failed), `revision`, `boundary_at` (import start B), `cursor_json` (tx marker / cb offset / vault job id), `rows_seen,new,dup,conflict,ignored,quarantined`, `pages_ok,pages_failed`, sub-budget `requests_budget, credits_budget, requests_used, credits_reserved`, `min_interval_seconds, next_read_at`, `completed_at`, `last_error`, `evidence_json`. Invariant `seen = new+dup+conflict+ignored+quarantined` (CHECK).
- `of_fans_history_cursor (account_id, fan_id PK)` mirrors native `OfRecentHistoryCursor`: `status` (needed/running/complete/gapped), `priority` (0 live fan, 1 recent inbound, 2 purchaser, 3 rest), `next_page` URL (validated by `history.validate_history_next_page`), `newest_message_id`, `oldest_message_at`, `pages, messages_seen`, `lease_token/until`, `retry_attempts, retry_not_before, last_error`.
- `of_fans_import_gap (account_id, gap_id PK)`: retained failed page or row: `source, fan_id NULL, cursor_ref, kind page|row, reason_code, http_status, attempts, exhausted, raw_sha256 (never body), created_at, resolved_by/at`. A source/fan with an unresolved gap can never be `complete`.
- `of_fans_message_fact (account_id, fan_id, message_id PK)`: first-seen provider facts of every outgoing message with media or price: `price_cents, media_ids_json, preview_ids_json NULL=unknown, locked_text NULL, from_queue NULL, is_opened NULL/True/False, opened_at, is_tip NULL, via history|webhook, raw_sha256`. Built from `offer_terms.from_history` semantics (NULL = unknown). Immutable except `is_opened` False->True (new row in evidence stays authoritative).
- `of_fans_read_meter (account_id, source, hour PK)`: `requests, ok, rate_limited, failed, credits_reserved, balance_first, balance_last (x-ofapi-credits-balance), rows, dispatched_unrecorded`.
Window state stays in `OfVaultSyncJob` (+ source row mirror); analysis state stays in `VaultItem` + `grok_calls`.

### 3.2 Reads, budget, rate (existing guard)
- `PreparationRequestGuard` allowlist gains GET `/chats/{fan}/messages` (limit<=100, order, `first_id/last_id` only), `/transactions` (limit, marker, startDate), `/chargebacks` (limit, offset, start_date), and the chat-list endpoint **only after the provider doc is checked**. Same reserve-first transaction, same account ceiling; additionally increments the matching `of_fans_import_source` sub-budget under the same lock and refuses when that source is spent (history cannot starve vault, vice versa). Sub-budgets and `min_interval_seconds` come from an explicit agency command (no defaults, like preparation form); registry ceiling still outer limit (`production_factory` `preparation.py:416-430`).
- Runner `fans_api_adapter/history_import.py::step(store, tenant, account, client)` called from `prepare_one` after the vault step (same advisory lock, same `PreparationRequestGuard`). Round-robin by source then by cursor priority/`next_read_at`; at most `pages_per_pass` (configured, default 1) pages. Refactor `FansBackfill._page` phases into shared per-source functions; `FansBackfill.run` and the pilot guard path stay unchanged.
- Classify history/transactions failures with `_fail` (transient/auth/schema + Retry-After), use `retry_delay`; failed page -> `of_fans_import_gap` + cursor untouched + `retry_not_before`; row-level `Refused` -> gap row `kind=row` and the page still completes (quarantine, not abort).
- Record every outcome in `of_fans_read_meter`; a reserved-but-unrecorded request shows as `dispatched_unrecorded`.
- Fairness across 10 accounts: existing per-account advisory lock and sequential `run_preparation_once` loop; a delayed/held account returns immediately (`prepare_one` `delayed/held`) so it cannot starve others; per-source `min_interval_seconds` and `pages_per_pass` bound any one account.

### 3.3 Coverage states (computed, never time-based)
Per source: `complete` only if the provider's end-of-pages was reached from a first page read after boundary B, no unresolved gap, counters invariant holds, and (chats) every known fan cursor is complete. `partial` = progress with open cursors/gaps/exhausted retries. `unknown` = not started, shape unverified, or fan universe not enumerated. Provider totals are not exposed for history/transactions in the reviewed client, so equality with a provider total is NOT claimed; coverage = cursor reached the end + our own counts reconcile.
Per fan: cursor complete AND transactions AND chargebacks complete AND no open gap for that fan -> `complete`.

### 3.4 Ownership (derive; do not stamp `is_paid`)
New `conversation_engine/history_ownership.py` (read only): for `(fan, media_ids)` returns per media `owned | unknown | clear_as_of(T)` plus evidence refs and counts by class. Evidence classes kept separate: free preview (in `preview_ids` or price 0), advertised card (price>0, queue/staff, not opened), sent card (our intent), unlock (`isOpened`/`messages.ppv.unlocked`), transaction (unlinked, no message id), reversal (`undo`/chargeback).
- `owned`: unlock evidence on a message whose fact has known previews; owned set = media minus previews.
- `unknown`: unlock on a message with NULL previews; any reversal not resolved; the fan's cursor or tx/cb sources not complete; any unresolved gap for the fan; message fact missing for an unlock.
- `clear_as_of`: only when the fan is complete and no evidence names the media. Never labelled "unowned".
- A bundle is excluded if any paid asset is `owned`; blocked (`unknown`) if any is `unknown`. Never split an old bundle price: `of_fans_message_fact.price_cents` is stored on the whole card only; offer import already groups by media set (`offer_import._merge`).
Wire-in (minimal, behind "account has `of_fans_import_source` rows" so legacy pilot is untouched): `commerce._unowned` (`commerce.py:72`), `media_delivery.assert_unowned` (`:100`), the catalogue shortlist eligibility, and `journey.backfill_complete` (use per-fan coverage instead of the weak non-pilot branch).
**What unknown blocks**: only a new paid card of a specific product to that specific fan (final dispatch + shortlist). It never blocks ordinary conversation, free content, other fans, or products with all media `clear_as_of`. Active-conversation fans get cursor priority 0 so their readiness arrives first.

### 3.5 Webhook/page reconciliation
At import start record `boundary_at=B` and require evidence the account receives webhooks (`OfFansWebhook` rows with `received_at>=B` or an explicit agency attestation) before any source can be `complete`. Page rows and webhooks converge through existing keys: message PK/`OfIngress` equivalence (`store.py:311-325`, conflicts quarantine), evidence `dedupe_key` (`unlock:/tx:/cb:`). Persist counts of duplicate/conflict/late rows in the source row; tx overlap 15 min already (`backfill.OVERLAP`). `webhook_conflict`/`event_scope` holds stay: a `tips.received` MATERIAL hold is surfaced in coverage as an open item, not ignored.

### 3.6 Window and analysis
- Window coverage reads `OfVaultSyncJob` + mirror to `of_fans_import_source(vault_window)`: selected count (<=1000), reached-end flag, boundary timestamp. Rotation test: new job -> new `selected`; `VaultItem`, `OfFansEvidence`, `of_fans_message_fact`, accepted intent snapshots unchanged.
- Descriptions for FansAPI accounts: new window-only batch runner `conversation_engine/preparation_describe.py` (reuses `_describe_one`, `assign_sync`, `_vision_budget`, GrokCall cost; fences model credential per account; NOT `native_family_clause`). Fetch only items in `selected`, one still per photo and bounded frames per video, never full-resolution outside the window and never for ownership; unusable -> existing `poster_only`/`fetch_failed` -> Miscellaneous/unresolved. Persist per account into `of_fans_import_source(analysis)`: described/failed-by-category/pending counts, `cost_millicents`, calls, bytes fetched, frames. Complete only when every window asset is described-and-stamp-bound or in a named terminal unresolved state.

### 3.7 API (additive, configuration purpose credential; `onlyfans_commands/configuration_api.py` pattern)
- `GET /accounts/{id}/history-coverage`: `{state, boundaryAt, sources[{source,state,counts,pagesOk,pagesFailed,openGaps,budget{requests,credits,used}, rate{reqPerHour,rateLimited}, cursorAgeSeconds}], fans{known,complete,partial,unknown}, window{selected,described,categorised,uncertain,miscellaneous}, analysis{...,costMillicents}, reconcile{webhooksSeen,duplicates,conflicts,late}}`.
- `GET .../history-coverage/fans?state=&after=&limit<=50` (review list with gap reasons); `GET .../ownership/{fanId}?mediaIds=<=50` (per-media state + evidence refs).
- `POST .../history-import` with `{action: start|resume|stop|retry-gap|dismiss-gap, expectedRevision, commandKey, actor, reason, budgets}`, idempotent via `OfLaunchCommand(kind='history_import')`, revision-fenced like `preparation.configure/stop`. `preparation.view` `historyCoverage/ownershipCoverage` now reads these states.
