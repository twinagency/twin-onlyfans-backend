# One-creator pilot ? 19 October 2026

The immediate target is one selected OnlyFans creator using existing vault media: connect and verify, synchronize, save creator/model settings, curate a ready catalogue item, enable on-request offers, explicitly activate a bounded account allowance, receive a direct request, reply/offer, and reconcile the exact purchase or reversal.

The operator editor reuses AccountAiConfig.ai_chatter_config_json and the existing immutable configuration audit. Enabling onRequestSalesEnabled explicitly sets pack_send_enabled, pack_on_ask_enabled and qualification_gate_enabled. Disabling it clears pack_send_enabled while retaining qualification and other controls. Unrelated settings are preserved. Invalid saved JSON or non-boolean switches refuse edits. Configuration revisions and fingerprints invalidate older plans at admission and egress. This setting does not activate delivery, reset allowance, clear takeover/no-contact or start a second AI/sales engine.

The paired creator-configuration contract is of-configuration.v3. Deploy backend and dashboard together. No schema migration is added. Purchase reconciliation must be enabled on the worker with ONLYFANS_LEDGER_ENABLED=1; media permission still requires complete recent ledger evidence. A failed or unsupported provider response retains the existing hold rather than inventing ownership or revenue.

No real OnlyFans account was connected when this work started. Live account/session/model and exact purchase-linkage acceptance remain required. Do not substitute RYC's Telegram account, select an arbitrary creator, or enable outgoing for a different account. Bulk upload, full dashboard video playback, full audience import, proactive sales and the proposed overview/channel-picker UI are deferred for this pilot.
