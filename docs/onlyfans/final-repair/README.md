## Changes in this continuation

- Durable commercial attempts on the existing conversation authority, with separate first-offer bubble and repeat-offer reply windows. Invitations, filler and split replies consume their actual allowance. Restarts, topic changes and configuration reloads do not reset an unfinished attempt.
- Projected boundary enforcement before releasing the whole response. An offer, specific invitation, one necessary clarification or recorded disposition replaces indefinite generic warming-up. Invalid decisions enter the existing operator review process.
- Item-specific invitations retain assets, amount, inventory revision and confirmed delivery. A short acceptance uses that association. One necessary ambiguity clarification retains the same item and quote; it cannot start a new selling cycle.
- Normal complete answers precede contextual cards. Recent refusals and ignored invitations are retained. Verified fresh requests for different content remain possible after purchase or an unpaid delivered card.
- Canonical price validation on existing catalogue/pack paths, explicit numeric budget checks, and quote metadata retained through the existing dispatch intent, provider receipt and local offer projection. The old blanket numeric-budget stop is narrowed for OnlyFans; actual hardship remains authoritative. No second pricing algorithm or sender was introduced.
- Rechecks for edited/retracted evidence, own confirmed bubbles, competing output, shared holds, media revisions and ownership. Specific invitation text uses commercial holds at the existing dispatch boundary. Positive native receipt pointers use the same dual-owner proof as the ledger; the retained pointer/lease still fences competing writers.
- The existing operator-case port now writes to R1's durable case owner. Unsupported customs remain owned review, rather than an invented automatic fulfilment promise.
- Old delayed nudges, discounts and purchase-triggered upsells are disabled while the new contextual live policy applies. They cannot override the fan-turn requirement. Existing positive receipt recovery remains separate and unchanged in purpose.
- Decision reporting distinguishes proposals, delivered invitations, undelivered invitations, paid cards, confirmed purchases, failures, no-offer attempts, pending invitations and extensions. First and repeat distributions remain separate.
- Additive migration `0108_commercial_progress`, regression repairs, isolated full-path tests and the evaluation harness. The test runner now records per-module outcomes/source hashes and bounds a hung module.
